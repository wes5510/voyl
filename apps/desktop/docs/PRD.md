# 📘 Voyl Product Requirements Document (PRD)

---

## 1. 개요

### 제품 목적

Voyl은 누구나 자유롭게 일할 수 있는 유연한 도구로, 개인의 생산성을 극대화하는 것을 목표로 합니다.

### 배경

기존 생산성 도구의 복잡성과 접근성 문제를 해결하기 위해 개발되었습니다. 로그인 없이 즉시 사용 가능하며, 오프라인에서도 동작하는 점이 핵심 특징입니다.

---

## 2. 범위

### 포함 범위

- Node 관리 (태스크, 폴더, 노트 등)
- 속성 관리 (마감일, 태그 등 사용자 정의 속성)
- 트리 뷰 (계층 구조 표시)
- 태스크 관리 (마감일 설정, 완료 체크)
- 간단한 검색 기능
- 오프라인 사용성
- 계정 없이 사용 가능

### 제외 범위

- 고급 뷰 (리스트, 캘린더 등)
- 작업 자동화 (예: 템플릿 기반 태스크 생성)
- 인박스 등은 초기 버전에서 제외됩니다.
- 모바일 지원은 초기 버전에서 제외됩니다.

## 3. 기능 요구 사항

| **기능**            | **설명**                                                            | **사용자 스토리**                              | **우선순위** | **기술 요구 사항**                |
| ------------------- | ------------------------------------------------------------------- | ---------------------------------------------- | ------------ | --------------------------------- |
| **Node 관리**       | Node 생성, 삭제, 수정, 이동. Node는 태스크, 폴더, 노트 등을 포함.   | "작업을 계층적으로 정리하고 싶다."             | 높음         | 트리 데이터 구조 구현             |
| **속성 관리**       | 사용자 정의 속성 추가 (예: 마감일, 태그). 그룹화 및 뱃지로 UI 표시. | "Node에 필요한 속성을 추가해 관리하고 싶다."   | 중간         | 유연한 속성 스키마 구현           |
| **트리 뷰**         | 계층적 트리 구조로 Node 표시, 펼치기/접기 가능.                     | "트리 뷰로 Node 구조를 한눈에 파악하고 싶다."  | 높음         | 효율적인 트리 뷰 UI 컴포넌트 구현 |
| **태스크 관리**     | 'task' Node에 마감일 설정 및 완료 체크.                             | "태스크의 마감일과 완료 여부를 관리하고 싶다." | 높음         | 날짜 처리 및 상태 관리            |
| **검색**            | 키워드 기반 Node 검색.                                              | "키워드로 Node를 빠르게 찾고 싶다."            | 중간         | 효율적인 검색 기능 구현           |
| **오프라인 사용성** | 인터넷 없이 로컬 저장소로 사용 가능.                                | "인터넷 없이도 Voyl을 사용하고 싶다."          | 높음         | 로컬 저장소 설계 필요             |
| **계정 없이 사용**  | 계정 생성 없이 즉시 사용 가능.                                      | "가입 없이 바로 사용하고 싶다."                | 높음         | 사용자 디스크 기반 데이터 저장    |

## 4. 세부 기능

### Node 편집

- 제목 수정, Backspace로 삭제, Enter로 새 Node 생성

### 속성 UI

- 속성은 그룹화되어 뱃지 형태로 표시

## 5. 비기능 요구 사항

| 항목   | 설명                                                  |
| ------ | ----------------------------------------------------- |
| 성능   | 수천 개의 Node도 빠르게 렌더링되고 탐색 가능해야 함   |
| 보안   | 데이터는 로컬에만 저장되며, 외부 서버로 전송되지 않음 |
| 접근성 | 인터넷 연결 없이도 전 기능 사용 가능                  |
| 사용성 | 파일 기반 작업에도 불구하고 직관적인 UX 제공          |

## 6. 기술 아키텍처

### 6.1 애플리케이션 구조

| 구성 요소       | 설명                                                    |
| --------------- | ------------------------------------------------------- |
| **클라이언트**  | React 기반 Electron 앱 (또는 React Native 모바일 앱)    |
| **로컬 저장소** | `.voyl/` 폴더 구조 기반 파일 시스템 (JSON, Markdown 등) |
| **보조 인덱스** | SQLite를 캐시로 사용하여 검색/정렬 성능 향상            |
| **플러그인**    | Dropbox 등 외부 동기화 및 CRDT 기능은 익스텐션으로 분리 |

---

### 6.2 데이터 저장 구조

Voyl은 로컬 파일 시스템을 \*\*데이터의 원천(Source of Truth)\*\*으로 사용합니다. 모든 노드는 `.json` 파일로 저장되며, 긴 본문은 별도 `.md` 파일에 저장됩니다. SQLite는 캐시로만 사용되며, 없어도 앱은 정상 작동합니다.

```
📁 .voyl/
├── nodes/
│   └── 74da8d.json         # 노드 메타데이터
├── content/
│   └── 74da8d.md           # 긴 본문 내용
├── log/
│   └── 2025-07-20.log      # 변경 이력
├── index.db                # SQLite 색인 (검색/정렬 전용)
├── config.json             # 앱 설정, 속성 정의, 플러그인 설정 등
```

---

### 6.3 저장 위치

- 사용자에게 앱 첫 실행 시 저장 위치를 선택하게 함
- 추천 위치: Google Drive, Dropbox 등 클라우드 싱크 가능한 디렉터리
- 저장 위치는 `.config/voyl/settings.json` 등에 기록됨
- 앱 내에서 변경 및 마이그레이션 가능

---

### 6.4 SQLite 캐시 전략

| 항목           | 설명                                                             |
| -------------- | ---------------------------------------------------------------- |
| 역할           | 검색/정렬/필터링 성능 개선용                                     |
| 포함 정보      | `id`, `title`, `parentId`, `tags`, `due`, `done`, `updatedAt` 등 |
| 재생성         | 앱 실행 시 자동 감지, 손상되거나 누락되면 전체 재빌드            |
| 삭제 노드 대응 | `.json` 실존 여부 기준으로 UI 렌더링 시 필터링함                 |
| 완전 제거 가능 | `nodes/*.json`만 있으면 캐시 없이도 복원 가능                    |

---

### 6.5 동기화 및 확장 전략

Voyl은 모든 외부 동기화 및 협업 기능을 \*\*플러그인(익스텐션)\*\*으로 처리합니다.

| 플러그인             | 설명                                         |
| -------------------- | -------------------------------------------- |
| `sync-dropbox`       | Dropbox API를 통해 `.voyl/` 폴더를 싱크      |
| `sync-google-drive`  | Google Drive API 연동 예정                   |
| `plugin-crdt`        | CRDT 기반 병합 확장 가능 (Automerge, Yjs 등) |
| `plugin-timemachine` | log 기반 시간여행 UI 제공 가능               |

- 변경 감지는 `updatedAt` 기반으로 처리
- 삭제된 노드는 `.json` 실존 여부로 판별
- 동기화는 **파일 단위이며, 전체 디렉터리 업로드 없음**

---

### 6.6 모바일 지원 (예정)

| 플랫폼       | 구현 전략                                                   |
| ------------ | ----------------------------------------------------------- |
| React Native | `react-native-fs`를 통해 `.voyl/` 내부 구조 유지            |
| 저장 위치    | 자동 경로 사용 (앱 전용 폴더), 단 Dropbox 연동 시 선택 가능 |
| 외부 동기화  | Dropbox API 연동은 백그라운드 플러그인으로 구현             |
| 캐시 사용    | SQLite 사용 가능 (`react-native-sqlite-storage` 등 활용)    |
